# Locked Decisions — Current

These decisions override conflicting legacy documents.

## Naming
- Current operating system/app: **The Black Poppy Flat**.
- Do not use **Canon** as the current product name.
- Legacy Canon/Atlas documents remain architecture/history references only.

## Storage and persistence
- `E:\Ethos` = authoritative source-design archive.
- `E:\Ethos\Claude\zorya` = local developer-handoff root.
- GitHub = authoritative code + Markdown + schemas + migrations + engineering docs + release history.
- Cloudflare R2 = deployment/runtime binary copies and served assets; not the master design-file archive.
- Cloudflare D1 = structured records, relationships, statuses, indexes, activity/history.
- Notion = operational work tracking only.
- Browser storage = cache/convenience only; never the sole home of important data.
- Google Drive is not part of the current Black Poppy Magik design-file workflow.

## Visual/brand direction — Black Poppy Magik
- Thick, abstract, monoline/sketch drawing language.
- Imperfect and hand-made, not generic occult clip art.
- Black poppy should be abstract enough to work like a glyph.
- No random skulls.
- No decorative filler just because it reads as 'witchy'.
- Avoid the word **witch** as the default personal/brand descriptor.
- Preserve approved artwork; assign it intelligently to products rather than redesigning everything.

## Product-system principle
This is not generic merch. Products are useful, beautiful objects from the Black Poppy world. Some carry the Black Poppy identity directly; some are artwork-led editions. Do not apply the same logo to every object.

## Flat principle
> Create it once. Lose it never.

Every durable object should have:
- permanent ID
- type
- title
- lifecycle/status
- provenance/source
- relationships
- version/history
- home
- next action when active

## Visual lifecycle

## Knowledge lifecycle
`Capture → Draft → Flat/Durable → Published → Archived`

## Preserve, don't destroy
- Archive/supersede instead of destructive delete.
- Version filenames/checkpoints during migration.
- Do not overwrite originals in Ethos.
